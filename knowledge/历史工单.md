# 历史故障工单（摘要库）

> 本库记录近 3 个月典型故障工单摘要，供排查时检索相似案例。完整工单见 ITSM 系统，此处为复盘后提炼的根因与经验。

## INC-2026-0918：spine1 与 leaf2 间 BGP 会话中断（2026-09-18）
- 现象：leaf2 与 spine1 之间 BGP 邻居中断，流量绕行 spine2，部分业务时延升高。
- 根因：当晚割接调整 spine1 的 BGP timer 配置，hold timer 参数双端不匹配导致会话反复超时。
- 处置：回退 timer 配置，clear ip bgp * 重建会话，22:40 恢复。
- 经验：BGP 参数变更必须双端同步核对；同类变更已纳入 checklist。
- 备注：leaf2 互联链路本身质量正常，若再次出现同现象，优先怀疑近期配置变更。

## INC-2026-0711：leaf2 SNMP 轮询风暴导致 CPU 冲高（2026-07-11）
- 现象：leaf2 CPU 持续 95% 以上，命令行卡顿，BGP 出现短时抖动。
- 根因：新接入的监控平台按 5 秒间隔全量轮询接口计数器，snmpd 进程过载。
- 处置：临时下线异常轮询任务，采集间隔调整为 60 秒，CPU 回落至 15%。
- 经验：新监控源上线前必须评审采集频率；全网采集基线为 60 秒。

## INC-2026-0822：leaf3 上联光模块劣化（2026-08-22）
- 现象：10.1.3.0/24 间歇性丢包，leaf3 Eth1/1 接口反复抖动（flap）。
- 根因：leaf3 至 spine1 链路光模块发光功率劣化。
- 处置：更换光模块后恢复。
- 经验：leaf3 为单上联设备，无冗余保护，是本网络已知的最高风险单点。

## INC-2026-0630：leaf1 冗余上联割接后未恢复（2026-06-30）
- 现象：巡检发现 leaf1 至 spine1 链路 down，但业务无影响（spine2 路径已接管）。
- 根因：机房布线调整割接后线缆未恢复；因无业务告警联动，延迟 3 天才被巡检发现。
- 处置：恢复线缆，接口 no shutdown，BGP 自动重建。
- 经验：冗余链路单点故障业务无感知，必须依靠接口级告警和定期巡检主动发现。
