# Runbook：设备 CPU 利用率高处理手册（RB-CPU-001）

> 适用场景：网络设备 CPU 持续高于 90%、管理面卡顿、控制面协议抖动
> 最近验证日期：2026-08-12 | 负责人：网络组

## 一、风险认知
设备 CPU 高本身不一定断业务（业务转发通常在硬件芯片完成），但会导致 BGP/OSPF keepalive 超时 → 协议抖动 → 业务间接中断，按 P2 处理。

## 二、定位步骤
1. `show processes cpu` 确认利用率（关注 5 秒/1 分钟/5 分钟均值）。
2. `show logging` 查找 CPUHOG、进程异常记录，定位高占用进程：
   - snmpd 高 → 监控系统轮询过于频繁（SNMP 风暴）
   - bgpd 高 → 路由震荡或大规模收敛
   - 转发相关进程高 → 可能存在环路或流量洪泛
3. 检查是否有新上线监控任务或近期配置变更（查变更工单）。

## 三、常见根因
- SNMP 轮询风暴（新增监控服务器、采集间隔过小）——本环境 2026-07 曾发生，见 INC-2026-0711
- BGP 路由抖动引发的持续收敛
- 广播风暴/环路（通常伴随接口流量异常）

## 四、处置
- SNMP 风暴：临时下线异常轮询源或调大采集间隔（需变更审批）。
- 路由震荡：定位震荡源邻居并做 dampening 或隔离。
- 短期无法定位且协议开始抖动：优先保障控制面，必要时重启进程（须组长审批）。

## 五、后续
- 事件结束 3 个工作日内补复盘工单，明确监控采集基线（全网基线 60 秒）。
